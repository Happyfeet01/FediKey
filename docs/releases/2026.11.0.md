# FediKey auf Basis von Misskey 2026.11.0

Testkandidat auf Basis des vollständigen Misskey-Releases `dd7b4905d715d2587fa2f2cb6a88ecac8878ef0d`. FediKeys Notizbearbeitung, History, ActivityPub-Updates, Argon2id-Anmeldung und verbesserte Nutzersuche bleiben enthalten. Google Analytics bleibt entfernt.

## Voraussetzungen und Start

- Node.js `^24.22.3` oder `^26.13.1`; Node 22 wird nicht mehr unterstützt.
- pnpm **12.17.0**. Das Dockerfile verwendet **Node 26.13.1-trixie** und installiert den festgelegten Paketmanager.
- Neuer Startweg: `node scripts/start.mjs`; mit Migrationen `node scripts/start.mjs --migrate`. `pnpm start` und `pnpm migrateandstart` bleiben verfügbar.
- Eigene systemd-/Startskripte mit relativen Pfaden in `NODE_OPTIONS` prüfen: Diese Pfade werden jetzt relativ zum Startverzeichnis ausgewertet.

Neben Paketaktualisierungen enthält der Stand die Upstream-Korrekturen für Quotes aus anderen Fediverse-Systemen, reaktive URL-/Zeitdarstellung, Deck-/Clip-Spalten, Streaming von Umfragewerten und weitere Client-/Serverfehler. Der Upstream-Changelog ist enthalten.

## Datenbank

## Installation nach Freigabe

Vor dem produktiven Upgrade Datenbank, Dateien und Konfiguration sichern und den freigegebenen FediKey-Stand zuerst in einer Testinstanz einsetzen. Die vorhandene instanzspezifische Compose-Datei und ihre Mounts beibehalten. In einer bereits korrekt auf FediKey umgestellten Installation den freigegebenen Quellstand holen und das vorhandene Web-Image neu bauen:

```bash
docker compose build web
docker compose up -d web
docker compose logs --tail=100 web
```

Diese Befehle setzen voraus, dass der Service tatsächlich `web` heißt und einen lokalen FediKey-Build verwendet. Bei einer reinen Image-Installation stattdessen den freigegebenen FediKey-Image-Tag setzen. Der normale Webstart führt ausstehende Migrationen aus. Danach Anmeldung, Uploads, Notizbearbeitung/History, empfangene Bearbeitungen und einen Neustart prüfen.

Ein älteres Image allein macht Datenbankmigrationen nicht rückgängig. Für eine vollständige Wiederherstellung das zusammengehörige Backup verwenden.
